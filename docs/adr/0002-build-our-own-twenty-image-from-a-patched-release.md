# Build our own Twenty image from a patched upstream release

Supersedes ADR-0001. The client does not want the Community and Documentation entries in the settings menu, and Twenty has no setting to hide them, so we now run our own image. The `jai-twenty-v2.41.0` branch is upstream tag `twenty/v2.41.0` plus our patches; a manual GitHub Actions workflow builds it and pushes `ghcr.io/codaswin/twenty:<tag>`, and `ops/docker-compose.yml` runs that image. The workflow is the build path because the dev machine has too little RAM for the front build; a local `docker build` of the same Dockerfile works on a larger machine. Patches are made on the release branch. `main` also carries the settings-menu patch because PR #6 merged it there; we never build from `main`, so that copy is harmless, but new patches go on the release branch only. Cost: each Twenty upgrade means cutting a new release branch from the new upstream tag, re-applying the patches and rebuilding. Keep the patch list short. Everything else (the Invoice app, config) still extends Twenty without patching it.
